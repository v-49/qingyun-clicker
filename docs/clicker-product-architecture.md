# 连点器整体架构讨论

2026-10-15。V2.0 正式版已接入原生绑定、短连发、按住连发、组合按住、全屏录制、组内序列回放与可逆编辑；混合执行支持并行叠加和软冲突轮换，录制支持3秒准备与可还原的结束剪尾。实现说明见 [同页录制方案](fullscreen-recording-plan.md)。当前交付见 [正式版记录](v2-release.md)，术语见 [GLOSSARY.md](../GLOSSARY.md)。

## 判断

统一为：**软件总开关 → 当前动作组 → 各行动作的触发、输出与执行参数**。

A/B/C 是场景配置；动作编排与操作录制是生成内容的两种入口；单键、组合和录制序列都是输出内容；短连发、按住连发和持续按住决定如何执行内容。这样同键连发、改键、组合绑定和序列回放共用一套绑定体系。

“编排”用于手动安排键鼠动作与顺序，替代容易理解成队伍管理的“编队”。“键程”若表示一次按下保持多久，产品统一叫“按下时长”；鼠标移动路径单独叫“轨迹”。

## DNF 连发例子的解释

未获得用户以前使用的脚本，不能断言其具体采用哪种机制。从描述归纳两种需要覆盖的行为：

| 配置 | 操作 | 结果 |
|---|---|---|
| X → X，短连发 3 次 | 按一下 X | 输出 3 次完整的 X 点按，达到次数结束 |
| X → X，按住连发 | 按住 X | 不断输出 X 点按，抬起结束 |
| A → A，短连发或按住连发 | 操作 A | 对 A 进行同键增强，与 X 使用相同机制 |
| A → B，持续按住 | 按住 A，再抬起 | B 按下，再随 A 释放；属于改键 |
| 侧键 → C + 右键，持续按住 | 按住侧键，再抬起 | 按配置先 C 后右键，结束时倒序释放 |
| T → 操作序列，短连发 1 次 | 按一下 T | 完整回放一次录制序列 |

短连发是固定数量的完整点按，与单纯保持一个 down 状态分开。数量、间隔和按下时长分别决定发送多少次、重复频率、每次按多久。AHK 官方文档分别描述固定次数重复、按下/松开与依据物理按住状态重复；这些资料支持能力划分，不证明旧 DNF 脚本的具体行为或目标游戏兼容。

## 三层职责

| 层级 | 内容 | 作用范围 |
|---|---|---|
| 软件全局 | F8 总启停、输入方式 | F8 启用或停止当前组 |
| 动作组 | 名称、动作列表、每行绑定；当前编辑入口和内容 | A/B/C 分别保存，第一版同一时刻仅一组启用 |
| 动作行 | 启/停、触发键、输出内容、执行方式、适用的时间和次数 | 独立响应该行触发，受所属组和总开关约束 |

“全局热键”表示主窗口不可见或失去焦点时也可响应；控制范围仍是当前组，并不因此运行所有动作组。

F8 启动后：自动行按原规则执行；绑定行进入监听，等待各自的物理输入；停用行不执行。F8 停止时，取消重复和未完成序列并释放实际持有的输出。切换动作组时先停止旧组并释放，新组等待再次启动。

## 每行动作的统一结构

每行分三块：

1. **触发**：自动执行，或绑定物理键/鼠标按钮。
2. **输出**：一个键、有序组合，或一段操作序列。
3. **执行**：执行一次/短连发 N 次、按住期间重复，或持续保持输出。

界面只呈现有效组合：

| 触发 | 执行方式 | 使用方式 |
|---|---|---|
| 自动 | 连发 | F8 启动后按间隔重复；保留现有连点 |
| 自动 | 按住 | F8 启动时按下，停止时释放；保留现有长按 |
| 按键 | 单次/短连发 | 一次物理按下执行 N 次，N = 1 即单次 |
| 按键 | 按住连发 | 从物理按下开始重复，物理抬起即结束 |
| 按键 | 按住 | 输出按下后保持到物理抬起；适用于单键或静态组合 |

录制序列支持一次、有限次或按住期间重复；包含移动、点击和等待的完整序列不显示静态“按住”选项。不能把“按住期间循环序列”和“把整段序列的所有键同时按住”混为一种操作。

没有资源争用时，短连发首次输出从物理触发时开始，不先等待重复间隔；有争用时等当前完整动作结束后优先执行。触发键很快抬起也完成本轮固定次数；总停止可以立即打断。按住连发和组合长按则在抬起时立即停止并清理输出，包括尚在等待中的请求。

同一行不重入：一次短连发执行或等待时，新的触发忽略，不累计排队；键盘自动重复不算新的物理按下。完成后需要新的物理按下才能再开始。

## 编排与录制在组内的关系

保留现有动作组与主列表，在底栏中间、定时关机旁新增录制按钮。手工新增与录制都是创建组内动作的入口，不再切换两套页面/列表，执行参数独立保留。

- 编排：手动新增单键、组合或步骤。
- 录制：点击时先停止当前执行，原按钮3秒倒计时后全局采集，用户切入全屏游戏；停止后生成一段操作序列并自动剪去最终返回软件的操作，保留可还原的原始内容。直接保存为当前组的一行动作，可点开查看/插入步骤并绑定触发键，不自动启动执行。
- 保存后的录制序列与手工动作都回到同一套绑定与执行设置。A 组可以同时包含 X 同键连发、侧键组合和 T 触发的录制序列，不需要复制成两个互不相通的配置体系。
- 录制过程中不执行原有绑定；停止录制不会自动启动 F8 总执行。录制控制、绑定执行控制与序列回放状态相互区分。

当前网页中的全局模式切换和两套列表是此前讨论壳子的实现。后续按此方案整合到动作组下时，保留旧数据并明确迁移，不把当前壳子视为最终数据层级。

## 时间参数与覆盖范围

| 参数 | 含义 | 适用内容 |
|---|---|---|
| 按下时长 | 单次点按保持时间 | 手工单键/组合的点按；每行“持续”，默认50 ms，直接修改 |
| 连发间隔 | 两次点按开始之间的时间 | 手工重复点按、短连发 |
| 次数 | 一个物理触发完成多少次动作 | 短连发，默认示例 3；单次为 1 |
| 组合间隔 | 组合内部先后按下的时间差 | C↓ 到右键↓等组合时序 |
| 步骤等待 | 序列中相邻片段之间的空档 | 手工步骤与录制序列 |
| 循环间隔 | 整段序列结束到下一轮开始的等待 | 录制序列的多次/按住重复 |

每行“持续”默认50 ms，已删除顶部全局时长和自定义开关。已录制序列保留自己的实际按下、松开和等待时序，持续按住也不套用固定点按时长。

若点按时长不小于连发间隔，有效周期按现有不重叠规则延长，不能因为设置了更小间隔就承诺更高频率。例：3 次点按、有效周期 I、单次时长 P，总输出时段为 `(3 − 1) × I + P`；不含系统调度误差。示例值用于解释，不作为 DNF 的已验证参数。

## 同键绑定必须确定的行为

- X → X 默认接管原始 X 输入，在本规则有效期间由连发输出替代，保证“3 次”不会多出未经计数的原始输入；不启用规则时 X 保持正常输入。
- 动作编辑直接显示“触发键原本功能也生效”。启用后物理输入照常传递，自动输出属于附加行为，不再承诺目标总共只收到 N 次。
- 只让真实物理事件触发绑定。本程序输出的 X 不重新触发 X → X；A → B 输出的 B 也不自动触发 B → C。
- 检测物理按下与抬起，不能用注入后的逻辑键状态判断玩家是否还按住 X。
- 第一版同一组内，一个触发组合只对应一行启用绑定；需要多个输出时编成该行的输出组合或操作序列。不同组可以重复使用 X，因为同时只启用一组。
- F8 总启停键及录制控制键不能同时被绑定行接管。
- 输出持有状态沿用统一管理，防止一路结束释放另一路仍持有的键。兼容的长按和修饰组合可以叠加；同键点按、录制与鼠标位置争用按完整轮次先后执行。自动永久长按与另一条点按/录制的同键需求无法轮换，启动前拦截。

AHK 的 `$` 热键机制也专门处理输出同一键导致的自触发；本项目使用原生输入时同样需要输入来源隔离。这是同键连发的执行要求，不要求用户切换输入引擎。

## 紧凑界面原则

A/B/C 继续使用原来的动作组入口。录制按钮放在底栏中间、定时关机旁，录制结果进入当前组；主列表不增加永久说明行。

旧自动动作维持原来的一行。绑定行简写 `X → X ×3 · 短发`、`A → B · 连发`、`侧键 → C + 右键 · 跟随`；录制绑定显示 `T → 序列名 · 单次/循环`。停用只置灰，不添加状态文字。点击“绑”或启用的绑定动作进入同一编辑框；未绑定动作仍直接录入输出。字段内采集输入，次数与时间固定为两行，不适用时置灰，原键功能直接显示。顺序协调与错误复用原说明槽，主列表不增加说明行。

自动行和绑定行均用行内“启 / 停”控制该行是否参与；绑定行只禁用两侧“间隔”和“按住”，编辑框不再放参与开关。F8 控制整个当前组。保存绑定不启动执行、不改变单条启停状态；解除恢复自动模式。录制中只显示必要状态，不弹出需要在其内部操作的捕获框。

## 实现边界与下一步顺序

现有 `ActionConfig` 包含可选 `trigger`、`burst`、`repeat_count`、`combo_gap_ms`、`pass_original` 与 `sequence`。`NativeInputMonitor` 管理物理事件，`NativeScheduler` 管理轮次、资源互斥、执行与释放；旧行缺少新字段时保持自动执行。触发键重复、占用总启停主键、自动永久长按导致无法轮换的同键需求在启动前阻止。其他资源重合按先后协调，多行兼容长按及通用修饰键由引用计数管理。

最小实现顺序：

1. 已完成已有动作的可选触发与固定次数执行；默认持续 50 ms、旧自动用法与配置键保留。
2. 已完成原组内录制入口、序列输出、全屏键鼠录制、步骤编辑与循环回放；保存后共用绑定入口，普通动作和序列共用调度器。
3. 目标游戏的输入兼容性仍需实际游戏验证，保持原生路径，不以切换 AHK 代替验证。

第一版暂不增加按一下无限切换连发、脚本语言、条件分支和绑定输出的链式触发。用户提出新场景后再扩展。

正式包为 `dist/QingyunClicker-v2.0.exe`，GitHub 发布为 `v2.0.0`。138 项单元测试通过，覆盖原有行为、可逆编辑、混合调度、资源轮换、绑定优先、中断释放与结束剪尾。真实Windows回放和录制线程检查通过；成品与缓存检查结果见正式版记录。目标游戏兼容尚未实测。

# 全屏录制：现有动作组内的实现

2026-10-15，内测 beta.11。已实现从全屏物理采集到组内保存、编辑、回放的链路，以及插入来源、可逆编辑、混合执行协调、录制准备倒计时与可还原的结束剪尾。

## 用户操作

底栏中间点击“录制动作”，先停止执行，原按钮显示“3s → 2s → 1s”，到时变为“停止录制”并开始采集。利用准备时间切到游戏，准备期间的键鼠动作不保存，跨过倒计时仍按住的键等松开后重新按下才录入。再次点击、F9或现有总启停键均可取消准备，不产生空录制。没有供用户在内部操作的录制弹框，不增加说明行或模式页。

结束无需延迟，按F9或现有总启停键立即停止，按实际停止时刻截断，GUI通知和线程退出的等待不加到时间线。点击本软件“停止录制”也可结束，点击软件窗口本身会过滤。

最终切回软件并结束时自动剪尾：匹配最近一次Alt+Tab（包括Alt+Shift+Tab及持续按住Alt选择窗口）与进入本软件的前台切换，从该次切窗操作开始删除后面的返回过程和等待。中途切回软件后又继续录制外部操作，取消此次剪尾；不因中途使用Alt+Tab删除游戏内容。切窗后在外部恢复实际操作，会取消旧候选。只将紧邻Tab、最近按下的Alt/Shift纳入切窗，保留游戏中长时间持有的修饰键。

直接用鼠标返回且无法确认Alt+Tab时，只以进入软件时刻截断，不猜测删掉之前的游戏轨迹。剪切按事件下标处理，同一时间戳的游戏动作仍保留；重算剪切点的持有状态，补齐配对松开。自动剪尾前的原始序列保存为现有还原基准，保存、重开及后续编辑后仍可还原，恢复可撤销。没有游戏内容、仅包含结束切窗时不生成空录制。停止时同时冻结窗口归属，之后GUI响应或窗口变化不改变剪切判断。

停止后将录制追加到开始录制时的动作组，不自动执行。初次保存默认单次；点击行内“循环”改为整段循环，间隔表示上一轮结束后的等待，默认1000 ms。右侧时长是录制本身的只读值，不用普通行的50 ms覆盖实际输入。

点击录制名称打开步骤编辑：名称、时间、按下持续、点击坐标可修改；鼠标轨迹分段显示。删除按键同时删除配对松开及该次系统重复。插入按键或组合时默认持续50 ms，可设置有限次数和间隔，后续事件整体顺延，原有重叠关系保留。单次试放等待3秒，使用总启停键可停止。

原录制步骤保持原表格样式；插入步骤以浅橙底色及“插入按键 / 插入按钮”标识，选中后仍保持区别，来源随保存与导出保留。原底栏提供撤销、重做及还原录制，还原本身也可撤销。首次修改时间线时保存原始事件与时长，后续插入、修改、删除不会覆盖该基准，保存后再打开仍可还原；名称和鼠标回放方式保持当前设置。旧版未保存来源与基准的录制，从本次编辑前的数据开始保留基准。

“绑”同样适用于录制行：单次、指定次数、按住期间循环。绑定后两侧自动模式置灰，中间“启 / 停”始终控制该行；停用摘要不追加文字，按旧版置灰。松开循环触发键或总停止时取消后续事件，并释放当前回放持有的键。

## 混合动作

| 内容 | 执行方式 |
|---|---|
| 普通间隔键、组合按住 | 原有自动周期或保持按住 |
| 一段录制 | 原时间顺序的单次或整段循环 |
| 插入录制中的按键 | 随该录制每轮回放，可有限次数连发 |
| 同组另一条间隔键 | 独立周期，与录制同时调度 |
| 同组绑定动作 | 总开关启动后等待物理触发 |

主列表是同时启用的动作集合，上下排列不代表前一行结束后执行下一行。完整的顺序放在同一录制内，独立无限连发仍放主组另一行。普通动作和录制共用调度器，序列等待不阻塞无资源重合的其他行。绑定只由物理触发，不再自动开始。

不同输出并行；同键、两段鼠标轨迹或屏幕位置回放与其他鼠标点击争用，按完整轮次先后执行。当前点按/组合/整段录制不被新的请求打断，内部时间线保留；当前轮次结束后，待执行绑定优先，然后自动行按到期时间轮换。共用资源时实际频率可能降低，不积压补发。

每行最多保留一个待执行请求。单次和有限次触发在抬起后继续完成；按住连发、跟随按住和按住循环在等待时抬起也会取消。总停止立即取消等待并释放当前输出。重复触发、占用总启停键、自动长按导致另一行始终无法执行的配置仍拦截，提示具体行与键；兼容的两路长按和手工组合修饰键可共享。

单次录制完成只结束该行，不关闭同组的间隔执行及绑定监听。组内没有未完成动作、无限自动动作或绑定监听时，才自动回到停止状态。

## 实现

| 文件 | 职责 |
|---|---|
| `recording_models.py` | 不可变时间序列、严格校验、物理事件收集与成对编辑 |
| `recorder.py` | 独立消息线程，全局键盘/鼠标钩子及后台 Raw Input 相对位移 |
| `recording_tail.py` | 最终返回候选、前台切换确认、事件边界剪尾与原始序列保留 |
| `scheduler.py` | 共用执行器中的序列状态、循环、触发、资源轮换与中断释放 |
| `input_names.py` | 编辑框与冲突诊断共用的按键名称 |
| `wininput.py` | 扫描码、绝对/相对鼠标移动、按钮及横纵滚轮回放 |
| `sequence_ui.py` | 录制步骤表、修改/插入/删除、单次试放 |
| `main.py` | 底栏入口、原组保存、启停、绑定及配置兼容 |

事件按单调时间 `t_us` 和同时间插入顺序保存，键盘保留VK、扫描码和扩展标记。鼠标保存按钮、屏幕位置、设备相对位移和原始滚轮增量。事件是执行真值，步骤表是其编辑视图。

软件自身的输入、准备时间内的动作、正式录制开始时已经按住且尚未释放的键、合成输入及录制停止键不进入录制。鼠标按目标窗口所属进程过滤，第一次点击软件窗口尚未切换焦点时也不收录；在外部按下、进入软件后松开的配对释放仍保留。停止时按实际停止时刻补齐仍持有的配对松开，仅补数据，不向游戏注入释放。线程退出后卸载钩子、撤销Raw Input注册并销毁消息窗口。

窗口变化使用 [SetWinEventHook](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwineventhook) 监听前台事件，在录制消息线程接收，退出时在同一线程卸载。窗口切换无输入事件时也能形成结束边界；不读取窗口内容或截图。

序列内嵌在原行动作配置中，无独立文件引用。继续使用 `QSettings("Clicker", "Clicker")`，保留用户组、总快捷键和窗口设置。含序列导出版本2，版本1仍兼容。损坏录制不会退化为自动按键输出。

录制容量上限20万事件、24小时，达到事件上限停止并保留已录内容。

## 鼠标及游戏验证边界

桌面默认使用“屏幕位置”。录制同时收集Raw Input相对位移，锁定/回中鼠标的游戏可在编辑框切换“相对移动”。回放只选择一种移动来源。屏幕坐标回放要求当前虚拟桌面边界与录制一致；相对移动不依赖该范围。

[Microsoft RAWMOUSE](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-rawmouse) 描述设备位移；[RegisterRawInputDevices](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerrawinputdevices) 支持后台接收。相对输入回放仍通过 [SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)，是否被具体游戏接受需要游戏内实测。

已验证：模型与配置往返、物理/注入过滤、插入/删除配对、混合调度、循环触发、停止释放、原生录制线程与Raw Input安装/卸载，以及真实Windows输出的键盘、按钮、位置与双向滚轮。真实输出测试被观察钩子截获，不进入用户应用。目标WeGame游戏尚未验证，不能据此声称解决其键盘屏蔽。

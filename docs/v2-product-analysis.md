# 轻云 2.0：键鼠操作录制

讨论稿 · 2026-10-10。基于仓库 `main` 的 `6c10525` 继续开发。桌面 beta.6 已实现按下时长、原生物理绑定、短连发及组合间隔，并统一停用显示。Windows 录制引擎尚未接入。最新入口与数据层级以 [同页全屏录制准备稿](fullscreen-recording-plan.md) 为准：底栏录制、结果进入现有动作组，本文的模式切换与独立列表描述保留为此前讨论记录，不作为后续实施入口。

同键短连发与整体层级见 [连点器整体架构](clicker-product-architecture.md)：动作组保存场景，触发与执行参数独立。行内绑定已落地；组内编排/录制统一入口和序列模型仍是后续方案。

## 判断

用户描述的功能属于 **键鼠宏录制与回放**。产品入口叫「操作录制」，结果叫「操作序列」，列表叫「步骤」。宏可以用在解释里，避免让普通用户先学习术语。

1.0：手动录入一个动作，设置间隔或持续按住；多个动作各自重复。

2.0：录下一段真实操作，把位置、按下/松开、持续时间、先后顺序保留下来，再按这段顺序执行。它记录输入事件，不录屏，也不自动理解按钮的业务含义。

产品流程：**切换操作录制 → 点击底部「启动」 → 切入全屏游戏并操作 → 全局快捷键停止 → 返回查看步骤 → 保存或回放**。启动后立即进入录制，无录制弹窗、体验区或强制倒计时。

录制器覆盖整个 Windows 桌面。主窗口失去焦点、最小化或切入全屏游戏都不能中断录制；只有用户暂停、停止或发生捕获故障时结束当前状态。用户不需要把操作限制在本程序窗口里。

## 连点模式的本轮需求判断

2026-10-10 补充。按下时长及原生触发绑定已实现；游戏兼容原因仍是分析，未执行游戏输入测试。

用户确认当前实际使用原生输入，并要求：**按住一个物理触发键时输出 C 与鼠标右键，松开触发键时全部释放**。游戏名称、实际游戏内测试结果尚未提供，因此“键盘被游戏屏蔽”仍是待验证原因。

实现优先级：先验证原生键盘在目标游戏中能否生效，再补齐组合动作的顺序、时间和物理触发控制，之后实现全屏录制与回放。录到事件不代表目标游戏接受回放输入。

### 当前代码已经具备与仍缺少的能力

- `InputBinding` 已能保存键鼠的有序组合。原生 `binding_down` 按存储顺序按下，`binding_up` 倒序释放；因此 C 与右键无需拆为两条独立动作。
- 原先 `binding_tap` 连续调用按下与松开，没有刻意等待，不能称为固定 1 ms。现已增加 `press_ms`：0 ms 保留立即松开的行为，正数由调度器独立安排释放。
- `_keyboard_input` 已优先使用扫描码；“改成扫描码”不能当作尚未尝试的新解决办法。
- 未绑定的 `hold` 在启动时按下、停止时释放；绑定行在物理触发键按下时按住输出，抬起时释放。全局快捷键控制当前组整体启停。
- 本轮按用户实际使用范围研究原生输入，不把切换 AHK 当作主要解决方案。

### WeGame 游戏键盘失效的判断

鼠标正常只能说明鼠标输入链路有效，不能证明键盘使用同一接受机制。先区分以下情况，不能直接认定整个平台屏蔽键盘：

| 待验证原因 | 判断依据 | 后续处理 |
|---|---|---|
| 按下与松开过快 | 当前短按没有刻意保留持续时间；部分游戏需要按下持续时间 | 比较 C 短按 50 / 100 / 200 ms 与持续按住。若只有较长按下有效，增加独立的“按下时长” |
| 权限或前台目标不一致 | SendInput 受 UIPI 限制 | 核对实际游戏进程的权限与前台窗口；不只核对 WeGame 启动器 |
| 游戏采用不同的输入接受机制或过滤合成键盘事件 | 延长按下和持续按住都无效时，需要进一步查证；Windows 可标记合成输入 | 做目标游戏专项兼容验证；若该输入通道被拒绝，不承诺单靠延时或扫描码能修复 |

这些是诊断路径，不是已确认的游戏原因。建议后续记录发送方式、事件顺序、按下时长、SendInput 返回数量及前台目标。SendInput 返回成功只表示事件插入 Windows 输入流，不表示游戏执行了对应动作。

### 组合按住的确定行为

初版将触发键与输出动作分开配置。以下按 C 也需要保持按住理解；若 C 只是点一下切换状态，应另用“前置点按”表达，不能混为一类。

```text
物理触发键按下：C↓ → 等待 Δt → 右键↓
物理触发键保持：C 与右键保持按下，不重复发送新的按下
物理触发键抬起：右键↑ → C↑
```

Δt 为可配置的两次按下间隔，与重复间隔、按下持续时间分开。测试数值可先用 30 ms，不视为任何游戏已经验证的兼容值。

必须满足：

- 等待 Δt 时触发键已抬起，就取消右键按下并释放已按下的 C，不能在用户松手后才发出右键。
- 只响应真实触发输入；标记并排除本程序生成的事件，避免自触发。键盘系统自动重复不应重启组合。
- 若物理右键本身就是触发键，严格保证先 C 后右键需要接管原始右键事件，不能让原始右键先到游戏再补 C。目标游戏是否接受这种接管需专项测试；用独立侧键或键盘键触发时不存在这一原始右键顺序冲突。
- 停止、切换配置、异常或游戏失去前台时，释放本动作实际按下的输出并停止后续等待。主窗口不可见不等于游戏失去前台。
- 多个动作使用同一输出键时管理持有状态，避免一个动作结束就提前释放另一动作仍需按住的键。

主界面保持一行动作，通过该行的组合编辑设置“触发键、输出顺序、按下间隔”。底部启动启用配置监听，物理触发键负责组合的开始与结束；已有无触发键的连点和持续按住配置保留原来的行为。

### 本轮已实现：按下时长

- 每行动作在间隔右侧固定显示“持续 [50] ms”，默认50，直接编辑，范围 0–99999 ms。已删除顶部全局时长与自定义开关，不增加界面行数。
- 新动作以及没有有效持续值的旧动作使用50 ms；已有逐行数值保留。JSON 只在动作行保存 `press_ms`，不再输出旧全局时长字段。
- “按住”模式不使用点按时长，持续框禁用；无绑定时从启动保持到停止，有绑定时从物理按下保持到抬起。后续录制回放将使用原始事件自身的时序。
- 重复间隔保持两次按下开始之间的时间。当时长不小于间隔时，不叠加同一动作，实际周期至少为时长加一个名义 1 ms 的松开阶段；系统调度不保证精确的 1 ms。需要鼠标高频、键盘保持更久时直接修改各行持续。
- 一行动作保持按下期间，其他行继续调度；共享输出按键按持有数量释放；停止、异常补发释放。旧 JSON 和 QSettings 配置键保持兼容。
- 最新内测包为 `dist/QingyunClicker-v2.0-beta3.exe`。持续时长支持原生与可选 AHK 生成逻辑，新增绑定/短连发/组合间隔仅支持原生。未实测 AHK 执行和目标游戏，不能宣称已修复 WeGame 键盘兼容。

### 绑定触发的层级决定（beta.2 已实现）

保留原来的全局启停用法，新增行内触发，不增加另一套“总启动”体系。

| 层级 | 管理内容 | 不承担的职责 |
|---|---|---|
| 软件全局 | 输入方式、F8 总启停 | 不因 F8 启动所有动作组 |
| 当前动作组 | 一套场景配置；启动后只有当前组参与执行或监听 | 不把动作组变成输出组合 |
| 动作行 | 启/停、输出组合、重复/按住、时间参数、可选物理触发键 | “启”不用于录入触发键 |

“全局快捷键”表示在游戏中也能响应；其控制范围仍是当前动作组。

启动当前组后：未绑定触发键的启用行照常自动执行；已绑定的启用行等待自己的物理触发键；停用行不执行也不监听。总停止释放全部输出。绑定不是独立于总开关的后台执行，否则用户无法明确判断软件是否还在工作。

触发键回答“什么时候执行”，输出组合回答“发出什么”，执行方式与时间回答“怎么执行”。点动作右侧“绑”分别设置触发键和输出组合；绑定后“间隔”和“按住”禁用，中间“启 / 停”控制本条是否参与当前组，编辑框不再放参与开关。行内显示“侧键 → C + 右键 · 跟随”等摘要。点击绑定摘要也进入编辑，未绑定动作仍直接录入输出。不增加主界面行。

例：F8 启动当前组；普通左键连点行立即运行；另一行绑定侧键，按住侧键后 C↓、等待组合间隔、右键↓，松开侧键后右键↑、C↑；F8 停止两行并释放。多个绑定行可各自触发，输出键共享时统一管理持有状态。绑定行选择“间隔”时只在触发键保持期间重复，选择“按住”时保持输出到触发键释放。

原生物理触发、注入隔离、固定次数短连发和组合间隔已通过单元与 Windows 输入链路检查。全屏录制仍待实现。当前监听与执行不限定目标游戏窗口，游戏前台丢失自动停止尚未接入。

### 默认50 ms的依据与范围

50 ms 是本次内测采用的快速点按试用值，由用户确定，不代表人体的固定时长。一项4人键盘实验测得手指接触键帽到离开平均约77.2 ms，但测的是打字，没有测刻意最快点按；接触时长也不等于键盘报告的 down/up 时长。[实验来源](https://backend.production.deepblue-documents.lib.umich.edu/server/api/core/bitstreams/c2113f50-8b35-4a1d-b06f-6af4921b1b63/content)

部分游戏需要按下后保持一段时间才接受输入；50 ms 是否足够需目标游戏实测，出现漏键时直接加长该行持续。Windows 调度不保证实际事件差精确到设定毫秒数。[AHK 官方关于按下时长与计时粒度的说明](https://raw.githubusercontent.com/AutoHotkey/AutoHotkeyDocs/v2/docs/lib/SetKeyDelay.htm)

## 首版做什么

| 能力 | 决定 | 原因 |
|---|---|---|
| 键盘单键、组合键、同时按多个键 | 做 | 保留实际按下/松开顺序，兼容 1.0 的组合动作 |
| 鼠标左/右/中/侧键，含键鼠组合 | 做 | 点击需要同时知道按钮、修饰键和位置 |
| 点击、长按、拖动、滚动 | 做 | 持续时间和移动路径会改变动作含义 |
| 时间间隔、暂停、继续 | 做 | 保留节奏；暂停不产生一段额外的等待 |
| 单次回放、速度、有限循环、循环间隔 | 做 | 先做到一段操作能可靠复现 |
| 查看原始事件、改等待/位置/按住时间、删步骤 | 做 | 人看步骤，回放依靠原始事件；让错误录制可修复 |
| 多份录制、重命名、JSON 导入/导出 | 做 | 延用现有分组和文件管理习惯 |
| 屏幕绝对坐标 | 首版默认 | 录在哪个屏幕位置，就在同位置执行；需要相同桌面布局 |
| 跟随目标窗口移动的相对坐标 | 后续 | 需要窗口识别、前台确认、客户区/DPI 变换，不能只给坐标减一个偏移 |
| 图像找点、OCR、自动等待界面出现 | 后续 | 它们是识别式自动化，可靠性和编辑模型明显不同 |
| 条件、变量、分支、脚本语言、后台定向回放 | 后续 | 首版先把连续操作录准、放准 |
| 把键盘输入自动变成文本 | 后续 | 输入法、布局、死键与快捷键都可能让键码和文字不一致 |

拖动和普通移动都默认保留轨迹，在步骤视图里收起连续移动，避免每挪动一像素出现一行。游戏是首版的实际使用场景，须验证全屏状态下的键盘、组合键、长按和鼠标捕获。鼠标在屏幕中自由移动时记录屏幕位置；游戏锁定或反复回中鼠标时，还需记录相对位移。只记录绝对坐标无法复现这类视角操作。

## 到底记录哪些信息

### 原始事件是执行依据

每次键盘/鼠标按下、松开、移动和滚动都带一个录制起点后的单调时间戳。键盘记录 VK、扫描码、左右修饰键、扩展键标记；鼠标记录按钮、虚拟桌面坐标、滚轮原始增量。同时记录屏幕边界、显示器布局、DPI/缩放和目标窗口的辅助信息。

示意（字段是拟议协议，并非已实现桌面模型）：

```json
{
  "schema_version": 2,
  "kind": "macro",
  "coordinate_space": "virtual_desktop_physical_px",
  "desktop": {"left": 0, "top": 0, "width": 1920, "height": 1080},
  "events": [
    {"at_us": 0, "type": "key_down", "vk": 17, "scan": 29},
    {"at_us": 24000, "type": "key_down", "vk": 67, "scan": 46},
    {"at_us": 76000, "type": "key_up", "vk": 67, "scan": 46},
    {"at_us": 95000, "type": "key_up", "vk": 17, "scan": 29},
    {"at_us": 600000, "type": "mouse_down", "button": "left", "x": 820, "y": 460},
    {"at_us": 690000, "type": "mouse_up", "button": "left", "x": 820, "y": 460}
  ]
}
```

不能仅存 `Ctrl+C` 字符串。`Ctrl↓ → C↓ → C↑ → Ctrl↑` 和 `Ctrl↓ → C↓ → Ctrl↑ → C↑` 的行为可能不同；A 和 B 同时按住也不同于先点 A 再点 B。

### 步骤是原始事件的易读视图

| 步骤 | 展示 | 可修改 |
|---|---|---|
| 点击 | 左键 · X/Y · 按住 80 ms | 位置、按钮、持续时间、前置等待 |
| 组合键 | Ctrl + Shift + A · 120 ms | 前置等待；重新录入组合及事件顺序 |
| 长按 | W · 1500 ms | 按住时间、前置等待 |
| 拖动 | 左键 · 起点 → 终点 · 路径 · 620 ms | 平移路径、持续时间、前置等待 |
| 滚动 | 垂直向下 · 原始增量 / 展示刻度 | 位置、增量、前置等待 |
| 移动 | 起点 → 终点 · 路径 | 平移路径、持续时间、前置等待 |

相互重叠的输入归为一个片段，并保留内部全部事件。连续 `Ctrl+C → Ctrl+V`、按着 W 点击鼠标等都不能通过简单拆行改变时序。修改、删除和重排应以可执行片段为单位，保证按下/松开成对；更细的修改进入原始事件视图。

「前置等待」是上一片段结束到本片段开始的空档；「按住时间」是片段内部的持续时间，两个数不能混用。回放速度同时缩放等待和片段内部时间；暂停和循环间隔独立处理。

## 界面取舍

沿用 `DESIGN.md` 的暖白、灰绿边框、浅冷灰启动按钮、纵向分组、紧凑动作行和底栏。

- 「连点模式 / 操作录制」并入原来的输入方式一行，放在输入方式右侧，不新增一行或增加说明文字。两种模式的列表和数据分开存储。
- 连点模式保持原来的输入方式、动作组、间隔/启/按住、录入和底栏位置。
- 操作录制显示录制组、紧凑步骤行和前置等待列。底栏右侧的「启动」负责录制，旁边的「回放」负责执行已有序列。
- 录制中在当前组标题内显示状态和时长，底栏「启动」变为「停止」，旁边显示「暂停 / 继续」。不弹框，不强迫全屏游戏出现浮条。托盘和全局快捷键负责主窗口不可见时的控制。
- 录完点击某一步才展开详情，位置、持续时间、等待都可编辑；默认先显示简明步骤。
- 录制快捷键建议 F9，回放沿用 F8，紧急停止建议 F10。全部允许修改并处理注册冲突；快捷键本身不进入录制序列。
- 开始录制前停止连点和回放；录制和回放互斥。运行中禁止切模式、删除或编辑正在使用的序列。
- 单次回放默认。速度默认 1 倍；有限循环默认 1 次；按下状态在停止、异常、退出时释放。

## 当前壳子的实现范围

网页壳子保留原有紧凑布局，表达切换模式、直接启动、暂停、继续和停止的状态，以及已有步骤的编辑、分组、导入/导出和回放时间线。

已删除录制弹窗、网页体验区和页面内键鼠采集。点击启动只切换壳子的录制状态；切走页面不会自动暂停。由于尚未连接 Windows 引擎，停止时不会凭空生成步骤。浏览器没有全局键鼠采集能力，不能据此宣称已录到游戏操作。

界面里不放「网页原型」「加载示例」、品牌口号、流程说明等无操作价值的文字。实现范围写在本文与 README，避免占用产品空间。上一版的网页体验数据仍保存在旧存储键 `qingyun-prototype-v2`，新版使用 `qingyun-prototype-v3`，只迁移连点配置；旧体验区数据不作为全屏录制展示。文件格式暂沿用独立标识 `qingyun-web-prototype`。

网页原型不实现全局快捷键、关机、后台输入、Windows 捕获或生产级 DPI 坐标转换。

## 桌面实现判断

现有可复用：PySide6 外壳、分组/捕获控件思路、JSON 管理、热键基础、SendInput 封装、停止/释放行为。

必须新增：

1. **录制器**：独立线程使用 `WH_KEYBOARD_LL` / `WH_MOUSE_LL` 和消息循环，回调只复制事件并立即返回，后台整理/保存。录制不依赖 Qt 主窗口的焦点或可见状态。过滤合成事件及本程序控制热键；自注入事件用标记识别，录制和回放互斥。全屏游戏使用锁定鼠标或相对移动时，必须评估并接入 Raw Input，记录相对位移；不能把回中后的屏幕位置当作真实轨迹。
2. **宏模型**：独立于 `ActionConfig`，保存版本、原始事件、步骤索引、坐标元数据。兼容读取旧文件，不能把旧动作直接解释成顺序宏。
3. **顺序回放器**：依据单调时钟的绝对截止时间调度，等待可被停止事件打断；按事件顺序送出输入，避免逐条 sleep 的累计漂移。轨迹和组合内部时序一并处理。
4. **鼠标坐标/滚轮支持**：现有 `wininput.py` 只发送按钮，需新增虚拟桌面绝对移动及滚轮。多屏可能有负坐标；声明 DPI awareness 后以统一物理坐标录放，不能把 Qt 逻辑坐标直接送出。
5. **运行保护**：记录按住集合，终止总是补发释放；录制在已经有按键按住时需等释放或提示重新开始；暂停先结束当前片段并清理状态，恢复后重新建立起点。显示器布局改变时先阻止直接回放并让用户重新录制/校准。

`scheduler.py` 当前按每个动作自己的 `interval_ms` 调度重复动作，并同时维持 hold 动作。它适合连点模式；宏回放应新增独立执行器。

屏幕坐标宏依赖窗口位置、分辨率和缩放。目标软件加载慢时固定等待可能不足；速度过快也可能漏操作。首版应提供慢速单次试放和可编辑等待。输入法文字、管理员权限边界与目标软件是否接收合成输入需要实测，不能宣称录制成功就一定能回放成功。

## 真正实现后的验收

- 点击启动后切入全屏游戏，主窗口失去焦点或最小化仍能捕获；全局快捷键可停止，快捷键和启动 / 停止按钮自身不进入序列。
- 区分自由鼠标的屏幕轨迹与锁定鼠标的相对位移；检查游戏中持续按 W、移动视角、组合键和键鼠同时操作的事件是否齐全。
- Ctrl+Shift+A、A+B、Shift+鼠标左键与按 W 同时拖动，事件顺序和松开状态正确。
- 单击/双击、鼠标长按、拖动曲线、正反向滚轮能复现；移动采样不破坏拖动路径。
- 暂停 5 秒再继续，不在序列中增加 5 秒空档；停止/异常/退出不残留按键。
- F9/F8/F10 和点击本软件控制按钮不被录入，回放不会被录制成新事件。
- 第二显示器、负坐标、不同 DPI、窗口移动/显示器断开有明确可测行为。
- 循环间隔和播放速度与预期一致；长序列没有明显累计漂移；导入恶意或损坏文件不会直接执行。
- 旧连点配置、快捷键和现有版本设置继续正常读取。
